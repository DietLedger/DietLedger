# Security policy

## Private reporting

Please report suspected security vulnerabilities privately to **Matthew Dumas** at **matt@dietledger.app**. Do not open a public issue containing exploit details, credentials or personal/health data.

Include the affected DietLedger version, installation method, impact and minimal reproduction using synthetic data. Never send passwords, API keys, session tokens or database dumps. Coordinate disclosure with the maintainer before publishing details.

## Updates and scope

Use the latest reviewed DietLedger release and its documented dependency/runtime requirements. There is no promised long-term support window for older beta versions. Dependency scans and passing tests are point-in-time checks, not a guarantee that a release or installation is vulnerability-free. Operator-managed ingress, backups and runtime updates remain necessary.
