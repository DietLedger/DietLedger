# Security resource admission and verification

Status: **implemented and verified in isolation** for M6/API20/HARD07; integration/release limits below remain. Owner: Matthew Dumas <matt@dietledger.app>.

## Objective and acceptance

Bound untrusted request, proxy, limiter, seed, and provider-error resource exposure without breaking approved native bundle and dataset workflows or changing authentication/session semantics.

Selected starting policies (test for exact over-limit behavior):
- Ordinary API request bodies: 1 MiB, including chunked/unknown-length requests.
- Native recipe-bundle JSON: 32 MiB.
- Admin dataset upload/download: 512 MiB compressed; 4 GiB inflated; max 10-minute job deadline; one active seed worker per API instance.
- Public Next proxy: at most 16 buffered requests and 2 upload streams; reject excess before buffering.
- Preserve the global rate limiter. Normalize peer identity without port; do not trust forwarded IP headers unless a configured trusted-peer policy explicitly authorizes them. Keep authentication/account-target buckets distinct from ordinary traffic.
- USDA transport errors and logs must not expose request URLs, API keys, or response bodies.
- Set no-store on authentication/token/secret/private API responses and compatible nosniff/frame/referrer protections. CSP must be staged to preserve Next/export workflows; HSTS is not enabled absent intentional HTTPS configuration.

## Implementation slices

1. Limiter identity and bounded visitor lifecycle: failing fake-clock tests for port-independent normalized addresses, route buckets, expiry, and capacity; then minimal limiter implementation.
2. Backend request admission: tests for cap/cap+1, chunked/missing/false Content-Length, route exceptions, and explicit 413 before JSON/multipart decode; wire globally without changing auth/session handlers.
3. Proxy admission/forwarding: test bounded admission before body cloning, supported request streaming/cancellation, sanitized forwarding headers and finite body size; verify the integration graph's Next 16.4.6 request APIs before claiming compatibility.
4. Seed bounds: fake transport/archive tests for compressed/inflated sizes, deadline/cancellation and single active worker; preserve existing parsing/food semantics.
5. USDA errors: injected fake RoundTripper with synthetic secret proves errors/logs are sanitized and response size bounded.
6. Response security policy: test no-store on sensitive responses and headers on API/proxy/Next responses. Avoid strict CSP/HSTS until compatibility/topology is verified.

## Implemented backend policy and focused evidence

- `resources.go` pre-reads the entire `MaxBytesReader`-bounded request before handler decode (including unread trailing bytes). Dataset uploads spool into owner-private temporary files, removed on return; JSON buffers and upload spools have process-local 16/2 admission slots. Exact upload path only gets the exception. Ordinary reads have a 30-second deadline; admitted dataset uploads have 10 minutes. Over-budget requests return explicit 413, saturation 503. The exact native bundle import path has a 32 MiB budget; pending-import decisions/ingredient edits and all other routes default to 1 MiB.
- The legacy `MAX_BODY_MB`/constructor argument no longer widens or disables route policy. Existing ordinary handler-local caps are fixed to 1 MiB and startup logs describe the selected route budgets; old configuration is inert, not an undocumented bypass.
- `RateLimiter` keeps the existing global 100/s, burst 200 limit, ordinary peer 30/s burst 60, distinct fixed-known-auth-route peer 1/s burst 10, one shared unknown-auth-route bucket per peer, and login/register account-target 0.1/s burst 5. Account targets are normalized and SHA-256 hashed; request bytes are restored. The visitor map caps at 10,000 entries and expires entries idle for 10 minutes on admission. At full active capacity, new keys fail closed rather than evicting active limits. Forwarding headers are ignored by default.
- `usda_live.go` only returns fixed transport/decode/read errors or numeric HTTP status. Response bodies/request URLs/raw transport errors never reach callers/logs. Search response limit is 8 MiB and existing 15-second timeout is retained; cancellation follows the caller; redirects are refused. Search terms are no longer logged.
- All API responses, including errors/public shares, have `Cache-Control: no-store`, `nosniff`, `DENY`, and `no-referrer`. No HSTS is set. These headers wrap rate-limit, CORS and admission failures too.
- Fixture inventory: available native recipe bundles are approximately 0.44–2.6 MiB (including the existing complete public-domain collection), below 32 MiB. The repository dataset catalog estimates Foundation 6.5 MiB, SR Legacy 205 MiB, Survey 64 MiB and Branded 3.1 GiB inflated; the selected 4 GiB ceiling covers those stated estimates, not a guarantee for future upstream releases. No upstream download was performed.
- RED: focused Go tests first failed on missing normalization/clock/admission/provider APIs, and new behavior assertions were then made GREEN. Command: `cd sync-server && env -u DATABASE_URL -u TEST_DATABASE_URL go test -run 'Test(USDA|RateLimiter|Resource|Sensitive|NormalizeRemoteAddr|ConvertUSDA|ParseFood)' .` passed. ## Seed and header evidence

- Fixed-source seed ZIPs download to private temporary files with an actual-byte compressed cap (512 MiB), a 10-minute context/client deadline and no redirects. Files are removed on every failure/success path. ZIP entry declared aggregate inflation is capped at 4 GiB, with at most 1,000 entries, actual entry size/CRC validation, cancellation-aware reads and no filesystem extraction.
- Dataset JSON streams one food at a time into 500-item database batches. Upload multipart parsing uses 1 MiB memory before disk spill, removes multipart files on all returns, validates the whole array before writing, then rewinds and imports 500-item batches. Background and uploaded jobs share one process-wide active-worker slot; an overlapping upload gets 503. Background pending work waits for the next processor poll.
- PostgreSQL seed batches and metadata accept context through `CreateFoodItemsContext`, `CreateSeedJobContext`, `UpdateSeedJobContext` and `ListSeedJobsContext`; cancellation applies to transaction begin, row locks, writes and job bookkeeping. Existing callers keep their source-compatible APIs. Background job polling has a five-second context; active work/status updates share the ten-minute job deadline. Multipart parsing also checks request cancellation before reading. Terminal completion/failure now has a separate fresh five-second cleanup context after work/client cancellation, and a durable, guarded expired-attempt reconciliation path described below. A late error can leave previously committed batches; this retains the existing batch-commit model rather than promising whole-dataset atomicity. Database outages may temporarily leave the last recorded status, but cannot hold the worker beyond the cleanup budget.
- Upload body read/write deadlines are extended deliberately to the same 10-minute request budget after admission. No future upstream dataset compatibility guarantee is implied; over-budget archives fail explicitly and require a reviewed policy revision.
- Next HTML receives `nosniff`, `SAMEORIGIN`, `no-referrer`, and **report-only** CSP (self scripts/styles with inline compatibility, self/data/blob/HTTPS images, self/data fonts, self connections, same-origin/blob frames, no objects, self base/frame ancestors). This is a staged policy, not XSS closure or enforced script isolation. API responses have no-store. No HSTS or HTTPS inference from untrusted forwarding headers.
- RED: seed/header tests first failed on missing bounded download/stream/worker APIs and missing Next header policy. GREEN: `go test -run 'Test(Seed|Resource|USDA)' .` and `npx vitest run src/security-headers.test.ts` (2/2).
- Full backend evidence: `cd sync-server && env -u DATABASE_URL TEST_DATABASE_URL=<exclusive-disposable-database> go test -count=1 ./...` passed on the final code including Docker-input, scoped recovery and bounded auth-route follow-ups (163s; earlier full runs also passed), with the new database identity check and canceled seed write test executed, not skipped. Existing native/staged/backup/nutrition/handler regressions were included. No real provider calls were used. Browser/external ingress/image verification has not run.

## Concrete Next 16.4.6 compatibility decision and evidence

Official Next documentation says middleware/Proxy automatically clones request bodies **before** user code, buffers up to its cap and silently truncates on overflow. Both the original Next 16.2.6 and integration graph's Next 16.4.6 source (`server/next-server` and `server/body-streams`) confirm `cloneBodyStream` precedes invocation, with a 10 MiB default. Raising that cap does not meet admission-before-cloning.

**Decision:** move the existing forwarding implementation from the convention-reserved `src/proxy.ts` to `src/lib/api-proxy.ts`, remove root `middleware.ts`, and enter through `src/app/api/[...path]/route.ts` (Node runtime, force-dynamic, every supported HTTP method). A first production build caught that merely removing root middleware leaves `src/proxy.ts` automatically detected as middleware. A failing regression now prohibits either convention filename. The rebuilt middleware manifest is empty and the API route is dynamic. No new proxy service/framework, business API, persistence, auth logic or host-published API port is introduced.

The transport admits at most 16 ordinary/native buffered requests and two upload streams before taking a body reader; counts actual bytes regardless of missing/false declared lengths; uses 1/32/512 MiB route budgets; and holds slots until response EOF/cancellation/deadline. Ordinary/native bodies buffer only after admission; uploads stream with fetch `duplex: half`. Deadlines are 30 seconds/10 minutes. Over-limit is explicit 413, saturation 503, upstream timeout 504, unavailable upstream 502, canceled clients 499. Upstream fetches never follow redirects or cache responses. Unknown API paths return no-store 404.

Forwarding headers are removed, not fabricated: all `x-forwarded-*`, `forwarded`, known client-IP aliases, Next middleware/control headers, and hop-by-hop headers (including Connection-nominated fields). The default does not trust XFF and deliberately does not assert loopback identity or HTTPS. Cookie, Authorization, Origin, CSRF and other end-to-end headers pass through. Every upstream `Set-Cookie` is copied separately using `getSetCookie`, including auth rotation/clear pairs. Fetch-decoded response encodings/lengths are removed. The API target remains internal/operator-configured; Compose/API host-port exposure is unchanged.

**Target graph verified:** Next 16.4.6, React 19.3.1, Vitest 4.1.12 from the separately owned dependency graph. This branch does not modify its manifest/lockfile. Official Node request adapter/types confirm Web request streams, AbortSignal and `duplex: half`. `npm run build:web` passed and emitted dynamic `/api/[...path]` with an empty middleware manifest. Independent `npx tsc --noEmit --pretty false` and focused lint passed. The build retains this branch's existing ignore-TypeScript option, owned by the dependency stream; it is not used as typecheck evidence. Symlinked external test dependencies cause standalone trace warnings, so this is not an image/standalone-artifact completeness claim.

**Executable transport evidence:** after `npm run build:web`, `node scripts/verify-resource-transport.mjs` passed against the real built Next 16.4.6 server and disposable loopback synthetic HTTP upstream (both closed afterward). It verified byte-for-byte a real repository v4 native fixture padded with 12 MiB of legal JSON whitespace (so even silent tail truncation is detected), a complete chunked 512 MiB syntactically formed multipart transport, explicit 413 at 512 MiB+1, ordinary/native cap+1 before upstream, separate Set-Cookie/auth-CSRF forwarding, forwarding-spoof removal, no-store, actual 16-request admission/release, client cancellation closing the upstream response, and staged HTML headers/no HSTS. The upstream is a transport fixture, not a claim of full application acceptance of arbitrary 512 MiB dataset contents. The complete Go suite separately verifies the API/store and new body/upload limits.

Focused unit evidence: proxy tests were RED against the old unbounded/full-header forwarding implementation; route-source regression was RED while convention-reserved `src/proxy.ts` still existed. `npx vitest run src/proxy-route.test.ts src/proxy.test.ts src/security-headers.test.ts src/lib/api-client.test.ts` passed 27 tests on the target graph. Final `npm test` passed 61 files / 557 tests. Final focused Go resource/limiter/seed/provider tests passed under `go test -race -count=1`. ## Implemented pre-merge follow-up: Docker inputs and terminal cleanup

- Docker build inputs must include only the new transport subtree below the otherwise excluded `src/app/api`. Add an ordered-ignore contract regression that fails against the current `.dockerignore`, while checking neighboring legacy/synthetic API paths remain excluded. This is input-contract evidence without running Docker; image verification remains separate.
- Seed work retains its ten-minute deadline. Terminal completion/failure uses a fresh **five-second cleanup context**, independent of canceled work/client context, before releasing the single worker. Persist a versioned per-attempt marker/deadline in the existing unused `seed_jobs.checkpoint` field when atomically claiming a pending job. No schema/new service is introduced.
- On cleanup database failure, log a synthetic-safe job-ID diagnostic and let the worker go. Each existing processor poll reconciles only expired, correctly versioned/validated markers created by this mechanism, using ID plus exact checkpoint and active-status guards. It marks those attempts failed; it never restarts jobs or resets legacy/unmarked/future/completed/foreign-attempt rows. This durable marker makes bounded retry possible after transient DB failure or process restart without an unbounded in-memory retry queue.
- The marker is `dietledger-resource-v1/<UUID>/<UTC deadline>` in existing `seed_jobs.checkpoint`. SQL claims only a pending, unmarked job; terminal SQL accepts only completed/failed and guards ID, exact marker and active status. The marker is recovery metadata, not an authentication credential. No migration is needed. Retry does not auto-resume data: a reconciled attempt is failed, and the administrator can explicitly start a new dataset import through the existing endpoint. Already committed food batches keep their existing upsert semantics.
- Outage/restart recovery: once PostgreSQL is available and the recorded attempt deadline has passed, the next five-second processor poll (itself bounded to five seconds) marks that attempt failed using its last recorded count. Before then status may remain in progress, but the worker is already free. Legacy/unmarked, future, completed and marker-replaced attempts remain untouched. No blanket startup reset or arbitrary-job recovery endpoint is added.
- Docker RED: `go test -run '^TestDockerContextIncludesOnlyAPITransport$' .` failed specifically because the route was excluded. GREEN after narrow ancestor/include/re-exclude rules with literal catch-all bracket escaping; sibling routes, debug children, `.env` and dependencies remain excluded. The contract evaluates this ignore file's ordered Go filepath rules/parent matches, not a built image. ## Remaining limits and explicit non-goals

- Limits/visitor state are process-local, not distributed. Defaults conservatively pool all requests behind the same socket peer. NextRequest supplies no verified remote socket identity; no trusted-XFF mode is silently enabled. A future trusted-edge contract requires explicit configuration/review, not a public header.
- This is not a total-heap guarantee: permitted bodies/individual dataset records, JSON objects and concurrency still consume memory; ZIP sizes/entry counts/job lifetimes are finite. Previously committed dataset batches can remain after later failure. During a database outage terminal state may be delayed until PostgreSQL recovers and the scoped marker expires; the existing processor retries reconciliation without retaining the worker or resetting arbitrary jobs. Last recorded counts may exclude batches committed immediately before a lost metadata update.
- CSP remains report-only without a collection endpoint. No browser PDF visual verification, real external ingress/TLS/HSTS, Docker image build, standalone packaging closure, final lockfile-integrated release build or live service change was performed. Header/session merge must retain the auth stream's cookie/CSRF rules; no session logic changed here.
- No dependency additions, database migrations, host API-port publication, or real provider/network probing. Disposable loopback HTTP fixtures are the only transport network tests.
