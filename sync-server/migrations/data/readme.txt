Glycemic Index / Glycemic Load Data
====================================

WHERE IT COMES FROM
-------------------
Glycemic Index (GI):
  A hardcoded, curated static database in src/data/glycemic-index.ts
  (GI_DATABASE). 231 entries of standard published GI values on the
  glucose = 100 reference scale. No external API fetches it.

Glycemic Load (GL):
  Not stored anywhere. It is computed at runtime in src/lib/glycemic-load.ts
  using the formula:

      GL = (GI * netCarbs) / 100

  where netCarbs = totalCarbs - dietaryFiber, scaled by serving multipliers
  and recursing into linked sub-recipes (depth-limited to 3).

HOW IT IS STORED
----------------
The GI values are NOT in the database. They live entirely in client-side
TypeScript. At runtime, findGI() in src/data/glycemic-index.ts performs a
case-insensitive SUBSTRING match against ingredient names, with the longest
matching keyword winning.

The carbs/fiber that feed the GL formula come from the ingredients table
(postgres), but the GI lookup table itself is browser-bundled code.

THE CSV (glycemic_index.csv)
----------------------------
231 entries expanded into 361 keyword rows, normalized format:

      id,gi,keyword
      1,100,glucose
      1,100,dextrose
      2,105,maltose
      ...

The id column preserves the original entry grouping (multiple keywords map
to a single GI value).

SUGGESTED SCHEMA + IMPORT
-------------------------
  CREATE TABLE glycemic_index (
      id      INT  NOT NULL,
      gi      INT  NOT NULL,
      keyword TEXT NOT NULL
  );

  \copy glycemic_index FROM 'glycemic_index.csv' WITH (FORMAT csv, HEADER true);

NOTE
----
A postgres keyword table gives exact or ILIKE '%keyword%' lookups, but it
will NOT replicate the current longest-match-wins precedence unless you
order by LENGTH(keyword) DESC in your query.

REGENERATING
------------
This CSV was generated by parsing src/data/glycemic-index.ts. If the source
database changes, regenerate the CSV from that file to stay in sync.
